# 移动端适配准则

本文档记录 `entbot.cn` 后续移动端适配的统一标准。当前首页 Hero 的移动端版本作为第一套确认基准，后续首页其他模块、产品页、案例页、服务页和关于页按同一原则执行。

## 1. 适配边界

- 只在移动端媒体查询内修改，默认断点为 `max-width: 760px`；HTML/CSS 图片 iframe 内部可使用 `max-width: 720px`。
- 不影响桌面端已经确认的像素级布局、比例、字号和模块位置。
- 移动端优先保证信息可读、模块完整、无横向溢出，不强行缩放整张桌面图。
- 每次只处理一个页面或一个模块，完成后用手机视口截图确认，再进入下一个模块。

## 2. 页面标题与正文

- 页面 Hero 主标题移动端字号基准：`38px-42px`，小屏可降到 `34px-38px`。
- 普通模块大标题移动端字号基准：`30px-36px`。
- 副标题和说明正文移动端字号基准：`16px-17px`，行高 `1.6` 左右。
- HTML/CSS 图片模块顶部说明文字如果承担模块标题或导语作用，移动端可使用 `18px` 左右、行高 `1.45` 左右，保证比普通说明文字更清晰。
- 移动端标题必须手动控制断句，不能依赖浏览器随机换行。
- 移动端标题里尽量隐藏中文逗号，改为自然分行表达。
- 每行标题尽量保持语义完整，例如“从诊断到落地 / 跑通第一批 / AI 增长流程”。
- 图片下方说明文字、模块内说明文字不能放大到接近主标题层级。
- 图片模块下方的说明标题不属于页面主标题。移动端统一比所在模块主标题低约 `2px-6px`，首页当前确认基准为 `30px`、行高约 `1.18`；说明正文使用 `16px`、行高约 `1.62`。
- 图片模块下方说明标题需要固定为两行时，必须按语义手动切分，并逐行检查是否在 `390px` 宽度下仍然保持单行。例如：
  - `从投放矩阵到账号群 / 发布增长作战台`
  - `从线索经营到招商 / 审批签约推进系统`
  - `从客户线索到 SOP / 执行运营中枢`
- 黑色结论卡、强调句等短文本不能为了单行显示压到过小字号；优先用 `14px-15px`、轻微字距压缩或调整容器宽度，保持可读。

## 3. HTML/CSS 图片模块

- 桌面端 HTML/CSS 图片保留原始视觉结构；移动端不使用 `transform: scale(...)` 强行缩放整张图。
- 移动端按内容语义重新切分模块，常用方式为：
  - 顶部目标/结论单独成组；
  - 中间流程、方法、核心图形单独成组；
  - 右侧列表或功能卡改为纵向卡片；
  - 底部流程、行业入口、标签区改为两列或单列。
- iframe 内部移动端应使用真实文档流布局：`position: static`、`display: grid/flex`、`height: auto`。
- 桌面端绝对定位元素在移动端必须重置 `top/right/bottom/left`，避免残留偏移。
- 外层 iframe 高度必须与移动端内容高度匹配，不用多余高度制造假留白。
- iframe 内部内容高度发生变化后，外层高度必须同步收紧。不要使用会被旧 iframe 高度托住的 `document.documentElement.scrollHeight` 作为唯一依据；优先读取真实内容画板或内容容器的 `getBoundingClientRect().height`，再回写外层 iframe 容器高度。
- 调整 iframe 高度前先确认内部文档实际高度；如果内部内容已经只有 `30px` 左右底部留白，优先收紧外层固定高度，而不是继续压缩内部模块。
- 文字必须是真实 HTML 文本，可选中、可换行、可单独调字号。
- 诊断/流程类 HTML 图片移动端可按“顶部判断说明 / 诊断卡片组 / 结论卡 / 流程沉淀”拆分成纵向文档流；桌面端的连接断点、断字标签等装饰在移动端换行后可以删除。

## 4. 模块间距与留白

- 已确认 Hero 图片模块移动端内边距基准：顶部 `30px`，底部 `30px`。
- 已确认挑战诊断模块移动端底部留白基准同样按 `30px` 左右控制；如果流程线或底部流程卡导致空白异常，应通过模块高度和 iframe 高度共同校准。
- 常规移动端模块左右内边距基准：`16px`。
- 同一组内卡片间距基准：`8px-12px`。
- 大组之间间距基准：`16px` 起，根据模块密度微调。
- 移动端缩小文字字号时必须同步收紧卡片高度、内边距和组间距，避免文字变小后仍保留桌面端高度，形成松散空洞的卡片。
- 图片模块之后的正文说明区按正常段落处理，移动端标题与正文间距建议 `14px-18px`，不要保留桌面端大列距造成的视觉空洞。
- 如果加了分割线、流程线或图标后导致底部留白不一致，优先压缩该组内部高度，而不是单纯增加外层高度。
- 分割线应位于对应图标或模块间距的视觉中线，不能偏上或偏下。

## 5. 卡片与图形

- 移动端卡片圆角通常使用 `12px-18px`，不要使用过大的桌面端圆角。
- 卡片内文字不允许溢出；必要时调整列宽，而不是缩小全部字号。
- 紧凑型卡片标题与说明文字要形成清楚层级。首页 Skill 模块当前确认基准：
  - 深色输入卡标题约 `22px`，说明文字约 `14px`；
  - 深色输入卡内部小卡标题约 `18px`，说明文字约 `14px`；
  - AI APP 列表卡标题约 `19px`，说明文字约 `13px`；
  - 字号缩小后卡片高度同步调整，输入小卡约 `80px`，AI APP 列表卡约 `64px-68px`。
- HTML/CSS 图片模块内的大标题也要遵守页面层级，不能比页面模块主标题更大。首页案例与行业模块当前确认基准：
  - 常规移动端约 `36px`；
  - `430px` 及以下窄屏约 `34px`；
  - 行高约 `1.08`。
- 多列摘要卡可使用“左右窄、中间宽”的比例，保证较长文字如 `Agent + Skill` 不溢出。
- 右侧图标或 SVG 必须收进卡片边界内，避免继承桌面端宽度导致外溢。
- 流程类元素移动端可改成两行显示；行业入口可改成 `2 x 2`。
- 诊断卡片、流程改造卡片等多卡布局在移动端优先保持与 Hero 模块一致的可用宽度，不要让内容因为容器过窄被挤压。
- 流程条从桌面横向改为移动端两行或纵向时，中间间距按普通段落/卡片间距处理，不保留桌面端长连接线的空白。

## 6. 验证标准

- 手机宽度优先检查 `390px` 左右视口，再检查 `430px` 和更窄宽度。
- 必须确认：
  - 无横向滚动；
  - 标题断句自然；
  - 逗号不造成孤立行或视觉错位；
  - 卡片文字不溢出；
  - 图标不超出容器；
  - iframe 不裁切内容，也没有多余空白；
  - 顶部和底部留白一致；
  - 缩小内部卡片或字号后，iframe 外层高度也同步收紧，没有被旧高度托住的底部空白；
  - HTML/CSS 图片后的说明区是正常段落间距；
  - 短强调句既不换行溢出，也不能小到不可读；
  - 桌面端没有被改动。

## 7. 禁止项

- 不为了移动端适配改动桌面端确认过的布局。
- 不把桌面端整张复杂图片直接缩小到手机宽度。
- 不新增无关内容、解释文字或装饰元素。
- 不通过隐藏核心内容解决拥挤问题。
- 不让文字重叠、卡片互相覆盖或图标悬到容器外。
- 不使用页面级大字号套在紧凑卡片、说明文字或图片注释上。
